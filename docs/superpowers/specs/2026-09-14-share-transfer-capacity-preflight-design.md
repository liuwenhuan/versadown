# 网盘分享转存容量统一预检设计

日期：2026-09-14

## 目标

当一个网盘分享必须先转存到当前登录账号的个人空间才能下载时，在“新建任务”确认阶段完成一次无副作用的容量预检。只有能够确认个人空间足够时才允许创建下载任务；空间不足、容量无法读取或所需容量无法确定时，直接向用户显示明确错误，并保证不创建根任务、目录组或任何子任务。

本设计在共享下载层统一实现决策逻辑，覆盖当前具备分享转存能力的夸克网盘、UC 网盘、百度网盘、迅雷网盘和阿里云盘。各网盘插件只实现自身的容量查询与响应解析，不复制容量计算、错误策略或任务原子性逻辑。

## 非目标

- 不为普通个人网盘下载增加空间检查；个人网盘文件已经存在，不需要转存。
- 不预留或锁定云端空间。预检与实际转存之间仍可能发生外部容量变化。
- 不在本次改动中清理用户已有云端文件，也不自动选择性跳过文件。
- 不改变分享文件列表的选择方式、目标目录选择、隐私下载或下载队列展示。
- PikPak 当前无需分享转存，不进入本预检；天翼云盘当前停用，不纳入实现和验收。

## 当前问题与根因

分享下载目前按以下顺序执行：

1. 根据分享计划构造选择结果；
2. 目录选择先创建目录组和根任务，单文件选择先创建下载任务；
3. 各叶子任务再尝试获取分享直链；
4. 如果网盘拒绝分享直链，才转入“先转存、再获取个人文件直链”的路径。

因此，容量不足发生在本地任务已经创建之后。目录分享会留下一个包含大量失败子项的目录组，单文件分享也会留下失败任务。以 2427 个文件的阿里云盘分享为例，这会把一个本应在确认阶段出现的账号空间错误放大为数千个下载失败。

问题不属于阿里云盘特例。五个网盘虽然用不同响应表达“必须转存”，但共享层的错误顺序相同，应该在共享能力层统一修复。

## 统一能力模型

### 容量值

在分享能力模块中增加不包含账号标识的容量值：

```rust
pub enum CloudTransferCapacity {
    Limited {
        total_bytes: u64,
        used_bytes: u64,
    },
    Unlimited,
}
```

`Limited` 的可用空间由共享层通过 `total_bytes - used_bytes` 计算。解析器必须拒绝字段缺失、非整数、负数以及 `used_bytes > total_bytes`；只有提供方明确约定的无限容量值可以转换为 `Unlimited`。

### 网盘插件接口

在现有 `ShareTransfer` 能力上增加容量查询：

```rust
fn transfer_capacity(
    &self,
    entry: &CloudShareResolvedEntry,
) -> Result<CloudTransferCapacity, QuarkError>;
```

接口以已经验证的分享条目作为上下文，允许插件复用当前登录会话、drive ID 和认证恢复机制。返回值只包含总字节数与已用字节数，不返回用户名、手机号、云端文件名、token 或其他账号信息。

只有声明 `transfer_capability` 的适配器需要实现该方法。这样，共享层能够从能力本身判断是否支持预检，不维护第二份提供方名单。

## 预检流程

增加共享层预检服务，并由 Tauri 命令包装到现有受监督会话执行机制中。预检必须在所有本地任务或目录组创建之前运行。

处理顺序如下：

1. 使用 `selected_share_download` 的验证结果，加载对应分享计划一次。
2. 从 `ShareTransfer::transfer_owner_fingerprint` 获取当前个人网盘账号的不可逆指纹。
3. 从该计划的转存日志一次性构造“当前账号可复用转存”的条目指纹集合。只有状态为 `Pending`、作用域为 `AccountV2` 且 owner 指纹匹配的记录才算可复用。
4. 从本次选择中排除这些已转存条目；它们不再消耗新的转存空间。
5. 如果没有剩余条目，预检直接成功，不调用容量接口。
6. 对第一个尚未转存的选中条目调用 `resolve_with_context`，只用它判断该分享在当前账号下是直链下载还是必须转存。
7. 如果结果是直链，丢弃临时签名 URL，预检成功，不查询容量。
8. 如果结果是 `TransferRequired`，对所有尚未转存的选中条目进行字节数求和。任一文件大小未知或累加溢出时，预检失败。
9. 调用对应插件的 `transfer_capacity`，由共享层计算可用空间并与所需空间比较。
10. 只有容量足够或容量明确为无限时，才进入原有任务创建和提交逻辑。

网盘对于同一个分享和当前账号的转存要求是分享级/账号级策略，因此用一个代表条目探测是否需要转存，避免在 2427 个文件上逐一请求签名直链。后续实际下载仍按文件执行原有直链解析与转存逻辑，不依赖预检返回的签名 URL。

`resolve_with_context` 可能为 UC、迅雷或阿里云盘轮换分享上下文。预检必须先把 `updated_context` 写回现有加密分享计划，再处理解析结果；除此之外，预检不允许产生本地任务或云端文件写入。

## 提交路径与原子性

以下两个入口都必须调用同一个预检服务：

- 用户在文件确认窗口点击“立即下载”的 `confirm_cloud_share_download` 路径；
- 分享链接解析后可直接自动提交单文件的 `parse_download` 路径。

调用点位于下载选项解析和选择校验之后、任何 `create`/`submit`/目录组创建之前。特别是目录流程，不能先创建根任务再预检。

原子性保证针对本地下载提交：预检失败时，任务存储中不会新增根任务、目录组、叶子任务或任务关联记录，也不会触发 `on_created` 事件。允许的唯一持久化是提供方上下文轮换写回原有加密分享计划，因为该数据用于保持分享会话有效，且不代表建立下载任务。

容量预检不会执行实际转存，也不会尝试“先转存一部分、失败后回滚”。因此预检失败不会在个人网盘制造残留文件。

## 各网盘容量适配

| 网盘 | 容量请求 | 解析规则 | 特殊值 |
| --- | --- | --- | --- |
| 阿里云盘 | `POST /v2/drive/get`，使用当前 bearer token 与 `drive_id` | `total_size`、`used_size`，允许 JSON 整数或十进制字符串 | `total_size == -1` 表示无限空间 |
| 夸克网盘 | 当前账号的 `clouddrive/member` 请求 | `data.total_capacity`、`data.use_capacity`，允许 JSON 整数或十进制字符串 | 无 |
| UC 网盘 | 当前账号的 `member?fetch_subscribe=true&_ch=home&fetch_identity=true` 请求 | `data.total_capacity`、`data.use_capacity`，允许 JSON 整数或十进制字符串 | 无 |
| 百度网盘 | 当前会话的 `/api/quota` 请求 | `total`、`used`，允许 JSON 整数或十进制字符串 | 无 |
| 迅雷网盘 | 当前 drive 会话的 `/drive/v1/about` 请求 | `quota.limit`、`quota.usage`，允许 JSON 整数或十进制字符串 | 无 |

容量请求沿用各插件现有的请求头、设备标识、cookie/token 刷新和挑战错误处理，不在共享层拼接提供方 URL。认证失效、风控、验证码等结构化错误保持原样向上传递，避免把需要用户操作的问题错误显示成普通网络失败。

## 错误语义

预检失败必须说明“未建立下载任务”，让用户明确失败发生在提交之前。

- 空间不足：`{网盘}转存空间不足：本次需要 {required}，当前可用 {available}，未建立下载任务。`
- 文件大小未知：`无法确定本次转存所需空间，未建立下载任务。请取消大小未知的文件后重试。`
- 容量读取失败或响应非法：`无法读取{网盘}可用转存空间，未建立下载任务，请稍后重试。`
- 认证、风控或验证码：保留插件返回的可操作错误文本，并补充“未建立下载任务”上下文。

`required` 和 `available` 使用现有下载确认界面的字节格式化规则，确保错误中的单位与文件列表一致。容量查询超时和临时网络错误按受监督只读请求的既有重试/会话恢复规则处理；最终仍无法确认容量时采用失败关闭策略，不猜测空间足够。

新建任务界面已经会展示后端确认错误，并且只有成功回调才关闭/切换确认流程。因此后端在创建前返回错误即可保留当前文件选择，不需要新增前端状态协议。

## 安全与隐私

- 代表条目探测产生的签名 URL 仅存在于当前调用栈，立即丢弃，不写入计划、任务、日志或 IPC 响应。
- 容量响应不落盘，错误中只显示汇总字节数，不显示账号身份或其他云端内容。
- owner fingerprint 继续使用现有不可逆值，不新增原始账号标识。
- 容量查询是只读请求；预检阶段不调用任何转存/复制接口。

## 并发与边界

容量预检不是云端配额预留。如果同一账号在预检之后被其他客户端占用空间，后续转存仍可能由网盘拒绝；这种竞争继续进入现有单文件失败与重试路径。此限制不能通过客户端原子事务消除。

为避免大分享产生二次平方级开销，转存日志只加载一次并建立集合，不能为每个条目调用会重复加载计划的 `reusable_transfer`。大小合计必须使用 checked arithmetic。

预检按本次选中的文件计算，而不是整个分享。已被当前账号可靠转存的选中条目不计入需要空间；其他账号留下的转存记录不能复用，也必须计入。

## 测试策略

根据仓库验证规则，本改动属于下载核心、网盘连接器和共享基础设施，执行相关定向测试与 Windows 发布构建，不默认运行全量测试。

### 共享层单元测试

- 直链可下载：不调用容量接口，提交正常继续。
- 必须转存且空间足够：容量只查询一次，允许提交。
- 必须转存且空间不足：返回明确错误，任务、目录组、子任务和事件计数均为零。
- 容量查询失败或响应非法：失败关闭，任务计数为零。
- 选中条目包含未知大小：失败关闭，任务计数为零。
- 已由当前 owner 转存的条目从所需空间中排除；其他 owner 的记录不排除。
- 全部选中条目均已转存：既不探测直链，也不查询容量。
- 代表条目返回更新上下文：先持久化上下文，再继续或返回错误。
- 2427 个条目的计划只加载一次、只探测一个代表条目、只查询一次容量。
- 自动提交单文件与目录确认两条命令路径均在任何任务写入前预检。

### 插件定向测试

阿里云盘、夸克、UC、百度和迅雷分别覆盖：

- 数字字段和十进制字符串字段的成功解析；
- 缺失、负值、非整数与已用空间大于总空间的拒绝；
- 认证/风控错误保持原有类型；
- 阿里云盘 `-1` 正确映射为无限空间；
- 容量请求不调用转存端点。

### 前端定向测试

确认后端拒绝时错误提示可见、确认窗口保留、没有触发创建成功分支。Vitest 命令必须包含 `--exclude '.worktrees/**'`。

### 真实验收

使用用户提供的阿里云盘分享 `https://www.alipan.com/s/2VsPJYYxm1u` 和当前实际登录账号完成：

1. 第一次打开新建任务即可一次性读取全部 2427 个文件；
2. 选择一个或少量文件且空间足够时，任务真实出现非零下载字节后停止，不要求全部下载；
3. 选择超过当前可用转存空间的集合时，新建任务阶段显示空间不足；
4. 空间不足后检查下载任务存储，没有新增根任务、目录组或子任务；
5. 通过请求记录确认失败路径未调用阿里云盘转存/复制接口。

如果实际账号空间足以容纳全部分享，空间不足的真实验收使用测试夹具或受控容量响应完成，不通过填满、删除或改动用户个人网盘制造条件。

## 完成标准

- 五个具备分享转存能力的网盘都通过统一能力接口报告容量。
- 所有分享提交入口在本地任务创建前完成预检。
- 空间不足、容量未知和所需大小未知均阻止提交，并给出可理解的错误。
- 直链分享和已经转存的文件不会被无意义的容量查询阻塞。
- 定向前后端测试通过，Windows 发布构建通过。
- 用户提供的 2427 文件阿里云盘分享完成一次性解析与真实非零下载验收。
