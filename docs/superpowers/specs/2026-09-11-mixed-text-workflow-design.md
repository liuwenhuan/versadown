# 混合文本下载与自动后处理任务设计

## 目标

用户一次粘贴包含多种下载协议、多个网盘分享链接、访问码、压缩密码和自然语言处理说明的文本时，应用创建一个持久化的“混合文本工作流”父任务。系统要在不要求用户使用标记语法的前提下，自动提取并去重资源、并发下载可确认的资源、生成受控的后处理步骤，并将经校验的最终产物交付到该任务独立的输出目录。

系统优先自动完成；只有资源访问、密码、操作对象等确实无法可靠确定时才等待用户补充。AI 不得获得压缩密码明文，也不得直接获得执行任意本机命令的能力。

## 范围和约束

- 一个混合文本任务的原始粘贴文本是不可覆盖的本地记录；不要求用户写入 `操作:`、`密码:` 等标记。
- 规则负责链接与证据提取、链接标准化、去重、协议/网盘适配器选择、访问码候选识别和本地安全检查。云端模型负责理解自然语言意图、建立依赖关系和生成受限自动化脚本。
- 磁力、HTTP(S)、迅雷链接及已接入网盘分享链接均进入同一父任务；每个资源仍交给对应现有下载接口或连接器。
- 第一阶段保证 Windows。语义化计划和归档预处理接口不得绑定 PowerShell；Linux/macOS 后续仅新增执行后端。
- Windows 执行器以 PowerShell 5.1 与随应用提供、经版本锁定的工具为基线，不依赖用户安装 Python、Node.js 或第三方解压软件。

## 持久化模型

新增 `mixed_text_workflow` 父任务及其版本化计划记录。其核心字段为：

- `raw_pasted_text`：本机明文保存的原始粘贴文本。
- `operation_plan_summary`：给用户阅读的自然语言流程摘要。
- `operation_plan`：本机保存的可执行结构化计划与受限脚本。
- `plan_revision`、模型端点/模型版本快照、创建/更新时间及当前状态。
- 子下载任务 ID、最终产物 ID、事件日志、派生产物关系、失败原因和用户补充说明。

每次用户补充或修改自然语言说明都创建新的计划版本，保留原始文本、旧计划、事件和已完成产物。普通下载子任务保存 `parent_workflow_id`；父任务存储每个候选链接在原始文本中的全部出现位置和周边证据。

相同资源按适配器生成的规范化下载身份去重，只创建一次下载；不同出现位置仍完整保留在父任务中。网盘链接的访问码、磁力哈希和短效直链由各适配器定义其稳定身份，不能只按可见字符串比较。

## 解析、规划与并发

处理管线如下：

1. 立即持久化原始文本，规则扫描候选链接及上下文位置，完成规范化、去重和提供方分类。
2. 相应协议或网盘适配器执行安全预检，取得可公开的元数据、目录结构和可用性。已确认可下载的独立资源立刻并发进入下载暂存区，不等待 AI。
3. 规则将资源清单、文本证据、预检结果和操作候选提交给云端规划器。文本中的压缩密码先替换为本地令牌，例如 `{{LOCAL_SECRET:archive_password:1}}`。
4. 规划器返回可阅读摘要和结构化 DAG；本地验证器检查节点引用、循环、文件作用域、路径安全、密码令牌和动作白名单。验证通过后以本地明文重新注入密码。
5. 下载完成、合并、归档探测、解压、校验等节点在依赖满足时自动运行。纯链接、没有明确后处理意图的任务，成功下载的源文件直接作为最终结果。

云端规划失败不会取消已启动下载；只有后处理部分转入“需要补充说明”。包含明显操作意图但对象、输入或顺序无法可靠确定时，系统展示具体歧义和已识别资源，等待用户补充后生成新版本计划。

## 受控脚本模型

AI 输出的是跨平台语义动作和受限脚本，而非可直接执行的 shell 文本。其动作包括：等待产物、重命名、二进制合并、归档探测、归档测试、解压、校验、移动到最终目录和生成清单。Windows 本地编译器再将它们映射为 PowerShell 5.1 与内置模块调用。

验证器只允许任务工作区内、已声明的输入输出路径和已注册工具；拒绝任意 shell 命令、网络访问、注册表操作、任意文件删除及未注册的可执行文件。AI 产生的脚本还必须通过静态参数和路径校验才会运行。计划执行期间只能写入暂存目录和最终输出目录。

AI 服务沿用现有可配置的 OpenAI 兼容端点、密钥和模型设置。每个计划版本固定保存当时的端点和模型快照；后续设置变更只影响新版本。

## 本地密码边界

原始文本、当前计划、弹窗输入和本地工具参数可按产品要求保存压缩密码明文。任何发送到云端的请求、响应、审计记录和错误内容只包含本地令牌，永远不包含密码明文；模型返回未知令牌、在不允许字段使用令牌或试图构造令牌时，计划验证失败。

遇到未知密码的加密归档时，对应归档节点进入 `awaiting_password`，并立即弹出任务级提示，显示归档名称、处理链路和原始工具错误。用户可输入密码继续、跳过该分支或终止整个任务。密码仅绑定当前归档节点；一个多卷文件集合视为一个归档节点，其他归档和嵌套归档不得自动复用该密码。等待密码期间，其他独立分支继续执行。

## 归档预处理与递归解压

应用提供独立的本地归档预处理组件，负责识别文件的真实布局，而不依赖扩展名：正常归档、正规多卷归档、通用分片、伪装头加归档数据和无法识别的数据。它与可替换的归档后端协作，先列出并测试，再实际解压。

- 正规多卷归档先识别并验证完整卷集，缺卷时明确失败，并从规范首卷交给归档后端；不得先盲目字节拼接。
- 仅对顺序连续且属于普通分片的文件，使用二进制流在暂存区合并，再重新探测和测试。
- 对图片、视频等伪装文件，预处理器以格式结构和归档测试确认真实起始偏移。验证通过后，在暂存区生成剥离头的派生归档；原文件始终不改写。
- 同一伪装文件内若存在多个通过验证的归档，按起始偏移顺序全部生成独立派生产物并解压到独立结果子目录。一个候选失败不会阻塞其他候选。
- 每一层解压产物都自动重新探测。可验证归档自动继续递归，直到没有可处理归档；内容哈希与父子链路防止循环和重复处理。
- 递归受最大层数、总展开体积、文件数量、扫描范围和运行时间等本地可配置护栏约束。超过护栏时保留现场并进入“需要补充说明”。

若归档后端不支持某种格式，预处理器仍可交付已合并或已剥离的派生产物，并报告缺失能力；它不伪造成功，也不会试图绕过加密或私有编码。

## 状态、失败与交付

父任务状态至少包括：`parsing`、`awaiting_access`、`downloading`、`processing`、`awaiting_password`、`needs_revision`、`verifying`、`completed`、`failed` 和 `cancelled`。状态应按子任务与操作节点聚合，并能显示每一分支当前产物、已完成步骤和原始工具错误。

下载网络错误可按确定的重试策略处理。语义错误、兼容性错误、无法映射操作对象、校验失败和资源护栏触发时，系统保留原始错误、实际检测结果、已完成步骤和可编辑的自然语言说明入口；用户补充说明后产生新计划版本。用户可随时终止任务。

每个混合文本任务拥有独立输出目录：

```text
下载目录/
└─ 混合任务-时间戳/
   ├─ 最终结果/
   └─ 任务日志/
```

成功完成且最终产物校验通过后，最终文件与任务日志保留；剥离副本、分片合并产物、临时解压目录及不属于最终交付物的源文件在关闭句柄后从暂存区永久删除，不进入回收站。原始下载文件本身若是最终交付物则不会删除。失败、等待补充说明或用户取消时，所有源文件、中间件和日志均保留，供重试和排查。

## 验收

- 一段混合文本能创建一个父任务，保留原文、所有候选链接的出现位置和版本化操作计划；重复链接只下载一次。
- 已确认资源在 AI 规划期间即可下载；纯链接文本完成后直接交付源文件。
- 云端请求、响应和日志不含压缩密码明文，本地计划可将密码传给当前归档节点；其他节点不自动复用。
- 已批准的结构化计划能在 Windows 基线环境执行，不接受任意 shell 或越界路径。
- 正规多卷、普通分片、带伪装头的归档、多候选伪装归档和嵌套归档均能按上述规则产生可追溯结果；缺卷、未知密码、格式不支持和护栏触发均不会破坏原始文件。
- 成功任务只留下最终结果和日志；失败、等待和取消任务能完整恢复现场；不同任务的最终结果互不重名覆盖。
