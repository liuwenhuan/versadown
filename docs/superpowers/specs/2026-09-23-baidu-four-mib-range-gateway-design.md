# 百度网盘 4 MiB Range 网关设计

## 目的与已确认事实

百度个人文件和分享转存后的个人文件应能通过同一下载路径完成大文件下载。对当前失败文件，两个同时进行、互不重叠的 4 MiB Range 均返回 HTTP 206 且各读满 4,194,304 字节；单个 8 MiB Range 返回 HTTP 403。这里的 4 MiB 是该文件和当前访问路径实测可用的请求上限，不宣称是百度永久公开规则。

现有 aria2-next 在 4 路下载约 972 MiB 文件时会请求约 122 MiB 的 Range。受限源站的本地回归测试证明，即使设置 `piece-length=4M`、`split=9`、`min-split-size=1M` 和 HTTP pipelining，实际仍可能请求 8 MiB，因此仅改 aria2 参数不能保证上限。

## 选择与范围

在应用内增加仅供百度下载使用的本地 HTTP Range 网关。云盘解析仍产生百度签名 URL 和临时请求头；提交 aria2 前，将目标换成仅监听 `127.0.0.1` 的随机令牌 URL。aria2 仍负责文件写入、按偏移合并、进度、暂停、续传、目录成员和任务状态；网关负责把每个 aria2 请求拆成多个不超过 4 MiB 的百度请求，并逐段校验后流式返回。

这比新增第二套文件写入器更少触及任务生命周期，也不修改随应用发布的 aria2-next 二进制。普通 HTTP 和其他网盘保持原路径；百度个人文件、百度分享转存文件及百度目录子文件共享这个网关。开发期不为未发布的旧网关状态设计迁移。

## 请求与数据契约

1. 网关注册项仅存于进程内，包含任务 ID、随机令牌、当前签名 URL、原始请求头和用户当前代理设置。令牌至少 128 位随机；本地 URL 不包含百度 URL、Cookie 或账号资料。仅接受已注册令牌、`GET`/`HEAD` 和单个合法字节范围。
2. 对 aria2 的闭区间 `Range: bytes=a-b`，按原有偏移顺序拆为 `[a, min(a+4MiB-1,b)]` 等小段；若 aria2 不发送 Range，先请求百度 `bytes=0-0` 取得总长，再以同样方式发送完整文件。`HEAD` 也只通过小 Range 获取元数据，不向百度发无 Range 的整文件请求。
3. 每次百度响应必须为 HTTP 206，`Content-Range` 起止与总长必须与请求及已知文件总长一致，正文长度必须精确等于该段长度。禁用内容编码变化；不完整、越界、200 整文件、403 或挑战页面均不能被当作成功字节。
4. 网关向 aria2 返回与其原请求匹配的 206（或无 Range 时的 200）、原文件总长和准确 `Content-Length`。每段最多缓冲 4 MiB；随后按顺序流式返回。多条 aria2 连接可并行，但每条上游请求都遵守 4 MiB 上限。网关不创建临时分段文件，也不自行拼接磁盘文件。
5. 第一段失败时向 aria2 返回失败状态；后续段失败时中断响应体，使现有引擎记录不完整 Range，而不是伪造成功。短效 URL 失效沿用现有云盘地址刷新和账号校验流程；刷新成功后更新对应网关注册项并由引擎继续可信的已完成范围。

## 生命周期、代理与安全

- 网关随应用进程启动并在退出时关闭。绑定随机本地端口；新提交先注册、后交给 aria2，提交失败撤销注册。完成、取消和回收后清除不再需要的签名 URL 与请求头。失败后若正在刷新或重试，则保留仍被旧 GID 引用的注册项直到新 URL 被接纳；刷新终止时清除旧项。
- aria2 到 `127.0.0.1` 必须直连，不通过用户设置的代理。网关到百度使用该任务提交时用户配置的 HTTP/HTTPS 代理；禁用未配置时的环境代理回退，不能因为网关引入绕过代理的外联。
- 原始百度 Cookie、签名 URL、代理密码只留在网关内存和上游请求中，不传给本地 HTTP 客户端、不写日志、不写普通任务记录。令牌不用于跨进程持久化。
- aria2 的旧会话文件可能保存已失效的本地 URL。应用重启时云盘任务继续按现有机制先暂停并重新授权、解析、提交新的本地 URL；绝不直接激活旧令牌。需用重启集成测试证明原生续传仍能复用可信已下载范围。

## 错误与验证

不新增不可翻译的用户界面文案。网关错误尽量映射到现有云盘提交失败、网络失败和地址刷新状态；确需新提示时先新增中英文本地化键。

验证先写失败测试，再实现：

1. 本地源站拒绝无 Range 或超过 4 MiB 的请求。以大于 32 MiB 的字节模式文件经实际 aria2-next 下载，断言上游每个请求都不超过 4 MiB，且最终文件逐字节一致。
2. 覆盖首段和中途 403、错误 `Content-Range`、短正文、非 Range 请求、尾段不足 4 MiB、并发请求；不得产生已完成的坏文件。
3. 覆盖暂停、恢复、签名 URL 刷新和应用重启后的续传；检查已完成范围不会因本地 URL 更换而被当作完整文件或从零重下。
4. 覆盖百度个人文件与分享转存文件经过同一网关，以及启用代理时只有网关上游使用代理。其他网盘的提交选项不变。

默认只运行涉及网关、百度提交和 aria2 续传的定向 Rust 测试；不因本设计、提交或本轮请求运行全量测试或生成原生二进制。
