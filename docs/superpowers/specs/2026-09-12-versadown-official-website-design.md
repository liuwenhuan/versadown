# VersaDown 官方网站设计

## 目标

为「万能下载 · VersaDown」建设独立的中文官方网站。网站面向普通用户，优先促成 Windows 版下载，同时以真实界面截图、简洁动效和透明的能力边界说明产品价值。

核心主张固定为：

> **什么链接，都交给 VersaDown。**

英文标语：*Every download, made simple*。

官网强调“一个入口处理主流下载来源和已授权网盘文件”，不承诺所有来源均可用、所有来源均可高速下载，且不承诺替代服务方会员权益或完整网盘服务。

## 品牌与受众

- 产品品牌为「万能下载 · VersaDown」，开发团队/公司品牌为 Gutta。
- 首要用户是收到网页链接、聊天文本、论坛资源或网盘文件的普通 Windows 用户，而不是主要寻找协议参数的重度下载用户。
- 文案优先说用户结果，避免将 HTTP、BT、RPC 等协议术语放进首屏；协议与服务的完整范围放在功能页、支持清单和文档中。
- 官网页脚以 Gutta 身份链接 X、Facebook、GitHub 与 Discourse。实际地址必须由 Gutta 提供后才可发布；不得猜测或伪造社交账号地址。

## 内容与路由

网站为多页静态站，包含以下公开路由：

| 路由 | 目标 | 核心内容 |
| --- | --- | --- |
| `/` | 建立价值认知并引导下载 | 核心主张、产品截图、常见来源、多个网盘一个下载入口、隐私下载、下载按钮 |
| `/features` | 用界面证明能力 | 粘贴与智能识别、已授权网盘、隐私下载、下载后处理的真实客户端截图 |
| `/compare` | 帮用户按场景判断 | VersaDown、Motrix、迅雷、官方网盘客户端四个独立列的公平对比 |
| `/docs` | 文档入口 | 快速开始、使用手册、FAQ；插件开发仅显示“即将推出”入口 |
| `/docs/<slug>` | 具体使用手册 | 单一操作问题、必要截图、就近 FAQ、目录导航 |
| `/download` | 下载和版本说明 | Windows 下载、macOS/Linux 即将支持、安装步骤、更新说明 |
| `/releases` | 完整发布记录 | 当前版本及历史版本的可切换更新说明 |

全站导航保留：首页、功能与截图、对比、文档、下载。下载入口在导航中始终可见。移动端使用菜单收纳次级导航，保留下载入口和核心卖点。

## 首页内容顺序

1. 首屏展示核心主张、产品运行截图及唯一主按钮“免费下载 Windows 版”。副文案说明 Windows 当前可用，macOS/Linux 即将支持。
2. 紧随其后展示常见来源：网页直链、磁力/种子、迅雷链接和已授权网盘；具体支持范围另行透明列出。
3. 首个关键功能是“**不必再装一堆网盘客户端。** 已授权网盘，直接下载。”截图应展示“我的网盘”、已授权服务和将文件加入下载队列的操作。
4. 使用“粘贴 → 识别与确认 → 下载并收尾”的三步流程解释 VersaDown 如何省步骤。
5. 用产品截图展示智能识别、统一任务队列和下载后处理；隐私下载以“**隐私任务，只在解锁后显示。**”单独呈现。
6. 提供公平对比、信任边界和再次下载入口。

## 多网盘与隐私下载的准确表述

- 网盘能力只能表述为“当前版本支持、且由用户本人完成授权的服务”。官网应展示实际服务清单和授权说明，不使用“所有网盘均可用”的绝对承诺。
- 官网不将 VersaDown 描述为完整网盘客户端，也不声称替代官方的在线文件管理、会员服务、云端生态、提速或付费权益。
- 隐私下载只能说明“隐私任务在本次应用会话解锁后显示”。必须在就近位置说明下载文件本身不会加密，不得将该功能包装为文件加密或端到端加密。

## 对比原则

对比页以“适合什么场景”为结构，并分别比较四类产品：

- **VersaDown**：适合希望把多来源文件和已授权网盘文件交给统一下载流程的用户。
- **Motrix**：适合需要标准下载协议和更深入下载管理选项的用户。
- **迅雷**：适合需要官方会员加速和迅雷云生态的用户。
- **官方网盘客户端**：适合使用对应服务的完整文件管理、在线功能和官方云服务的用户。

对比页不得将迅雷与官方网盘客户端合并成一个对象。第三方能力可能变化，页面需附带“以各自官方说明为准”的提示。

## 视觉、截图与动效

- 视觉采用“清爽可信”方向：明亮蓝绿、充足留白、清晰信息层级；避免面向普通用户的过强技术感或堆叠装饰。
- 首页和功能页以真实 VersaDown 客户端截图为主，抽象图形只作背景。正式素材必须来自可复现的产品界面，不得把虚构界面当作真实截图。
- 动效只表达状态与因果：链接输入、识别、进度变化、截图随滚动进入。不得用动画暗示所有来源均高速或必然成功。
- 所有动效尊重 `prefers-reduced-motion`；关闭或减少动态效果时，内容与操作必须仍完整可用。
- 截图必须有有意义的替代文本；移动端单列展示，确保文字与关键界面细节可读。

## 独立官网架构

官网在仓库内作为独立静态子项目维护，建议目录如下：

```text
website/
  src/
    pages/                 # 路由页面
    components/            # 导航、页脚、截图模块、更新说明、FAQ
    content/               # 下载配置、发布记录、文档目录、FAQ、社交链接
    styles/                # 设计令牌与响应式样式
  public/
    screenshots/           # 经审核的真实客户端截图
  package.json
```

- 官网使用独立的 React/Vite 构建和静态路由，不能导入桌面应用的 Tauri API、状态库或业务组件。
- 官网的截图、页面组件和内容配置独立于桌面下载器，避免营销站迭代影响桌面程序。
- 发布前只生成静态站点产物；不需要运行桌面应用或 Rust 测试来验证官网。

## 内容数据与状态

下载信息、发布记录、文档目录和社交链接必须来自集中配置，而不是分散硬编码到页面。

- `downloads`：每个平台记录可用状态、下载 URL、系统要求和显示文案。Windows 只有在 URL 存在时显示可点击下载按钮；macOS/Linux 在未发布前只显示“即将支持”。
- `releases`：每条记录包含版本标识、发布日期、适用平台、更新条目和是否为当前版本。下载页默认渲染当前版本；发布记录页可切换历史版本。
- `docs`：记录导航层级、文章 slug、标题、FAQ 关联项和插件开发的“即将推出”状态。
- `social`：保存 Gutta 的外部主页 URL。缺少配置的社交入口不得伪装成可点击链接。

浏览器请求路由后，页面读取对应静态内容配置并渲染。当前版本从发布记录的当前标记或发布顺序推导，不能在页面中另外写死。历史发布记录为空时，更新说明只显示最新版本并隐藏历史切换入口。

## 错误与降级

- Windows 下载 URL 缺失或无效：隐藏主下载按钮，改为可读的“下载暂不可用”状态；不能指向占位 URL。
- 截图资源缺失：显示带替代文字的静态容器，且记录构建失败或内容校验错误，防止发布带破图的页面。
- 发布记录中没有当前版本：构建检查失败；不可随意挑选一条旧记录冒充当前版本。
- 不存在的文档 slug：渲染网站内 404，并提供返回文档首页的链接。
- 外部社交或下载链接打开失败由浏览器处理；官网不嵌入第三方社交流，从而不阻塞页面加载。

## 验证

官网实现后的最小验证集：

- 对页面路由、导航、下载状态、发布记录默认/历史切换、缺失配置降级和 FAQ 展开运行定向前端测试。
- 用桌面与移动视口检查首页、功能页、对比页、文档和下载页的响应式布局；确认截图可读、表格可横向浏览或适当折叠。
- 在启用与禁用 `prefers-reduced-motion` 的条件下检查动效降级。
- 使用真实截图和真实配置进行构建，确保无缺失资源、坏链接或硬编码“最新版本”。
- 运行官网子项目的构建命令。现有桌面程序不因官网改动默认运行 Rust 测试或全量 Vitest。
