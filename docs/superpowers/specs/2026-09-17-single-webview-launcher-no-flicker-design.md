# 单 WebView 悬浮窗无闪烁设计

## 目标

保留一个悬浮 WebView，不引入第二个 WebView 或新的 UI 运行时。六边形图标在左右键打开、关闭和切换弹窗时不得出现空白帧、重绘闪烁或位置跳动。

点击只改变同一 WebView 内部的可见内容。点击期间不得改变原生窗口的位置、尺寸、可见性或裁剪区域。

## 当前问题

当前紧凑窗口为 64×64。打开左键面板或右键菜单时，前端调用原生边界更新命令；Windows 实现先清除窗口区域，再通过 `SetWindowPos` 改变位置和尺寸，最后重新应用窗口区域并要求重绘。WebView2 因此重新合成透明窗口表面，六边形会短暂消失或闪烁。

CSS 隐藏过渡期弹窗只能避免弹窗被裁切，无法阻止原生表面重建。

## 架构

### 固定画布

悬浮窗口在初始化时创建为固定最大尺寸，之后不再因菜单开关改变尺寸。

- 画布宽度按最大弹窗宽度确定。
- 画布高度容纳六边形、间距和最大弹窗高度。
- 六边形在画布顶部或底部使用固定锚点。
- 左键面板和右键菜单始终挂载，仅通过可见性和交互状态切换。
- 六边形组件与弹窗状态隔离，弹窗切换不得卸载或替换六边形 DOM。

画布方向在悬浮窗拖动结束、显示器变化、DPI 变化或工作区变化时更新。普通点击沿用已计算的方向：上方空间不足时弹窗位于六边形下方，否则位于上方。

### 原生输入区域

固定透明画布不能遮挡后方应用。原生层维护当前可交互区域：

- 收敛：仅六边形区域。
- 左键展开：六边形与新建下载面板区域。
- 右键展开：六边形与菜单区域。

透明且不属于活动区域的位置必须穿透到后方窗口。更新输入区域不得改变窗口的视觉裁剪区域，也不得请求整个窗口重绘。

平台适配封装为同一接口：

- Windows：窗口命中测试在活动区域外返回 `HTTRANSPARENT`。
- macOS：宿主视图在活动区域外不返回命中视图。
- Linux X11：更新 X Shape 输入区域。
- Linux Wayland：在协议允许时更新 surface input region；绝对定位和置顶继续遵守当前桌面环境能力。

首个交付目标是保持 Windows 当前行为并消除闪烁，同时将输入区域计算和平台调用分层，避免把 Windows API 泄漏到前端状态机。

### 状态机

悬浮窗只允许以下显示状态：

- `compact`
- `quick-add`
- `context-menu`

所有状态转换串行执行。左右键快速交替时，后一个意图覆盖前一个意图，不并发执行原生操作。

状态转换顺序：

1. 更新目标弹窗内容和方向。
2. 更新原生输入区域。
3. 在同一渲染提交中切换弹窗可见性。
4. 保持六边形节点、窗口边界和视觉区域不变。

关闭、Esc、点击外部或开始拖动时切换为 `compact`，只收缩输入区域并隐藏弹窗。

## 前后端边界

前端负责：

- 显示状态机。
- 弹窗内容与主题。
- 根据预先计算的方向选择布局。
- 将活动矩形列表发送给原生层。

Rust 原生层负责：

- 初始化固定窗口边界。
- 根据 DPI 将逻辑矩形转换为物理坐标。
- 应用平台输入区域。
- 跟踪拖动结束、显示器、DPI 和工作区变化。
- 返回新的布局方向和固定画布位置。

打开或关闭弹窗时，前端不得调用现有的 `set_launcher_bounds`、`set_launcher_compact_shape` 或窗口 `show`/`hide`。

## 异常处理

- 输入区域更新失败时保持上一份有效区域，不得退化为覆盖整个透明画布。
- 布局方向计算失败时沿用上一方向。
- 主题、下载速度或主界面状态更新只能更新对应内容，不得触发窗口边界同步。
- 应用退出期间忽略新的悬浮窗状态转换。

## 测试与验收

### 前端测试

- 左右键切换不会调用任何窗口边界、裁剪或可见性命令。
- 六边形 DOM 节点在 `compact`、`quick-add` 和 `context-menu` 之间保持同一实例。
- 快速左右键交替最终只显示最后请求的弹窗。
- Esc、点击外部和拖动恢复 `compact` 输入区域。

### Rust 测试

- 逻辑活动区域在不同 DPI 下正确转换。
- 三种显示状态生成正确的输入区域。
- 弹窗开关不会更新窗口位置、尺寸或视觉区域。
- 上边缘使用下方布局，其余位置优先使用上方布局。

### Windows 集成验收

- 左右键交替点击 50 次，窗口位置、尺寸和视觉区域始终不变。
- 点击前后六边形截图像素一致，不出现透明帧。
- 透明区域不拦截后方应用鼠标操作。
- 顶部、底部、多显示器和不同 DPI 下六边形不移动。
- 拖动、输入框焦点、Esc 和菜单动作保持正常。

## 迁移顺序

1. 为现有窗口边界调用和六边形节点稳定性补充失败测试。
2. 引入显示状态机和活动区域模型。
3. 将悬浮窗口改为固定画布，但暂时保持现有视觉布局。
4. 实现 Windows 部分命中测试与输入穿透。
5. 移除点击路径中的窗口缩放、裁剪和过渡等待。
6. 完成 Windows 集成验收。
7. 在后续跨平台交付中分别实现 macOS、X11 和 Wayland 输入区域适配。

## 非目标

- 不引入第二个悬浮 WebView。
- 不引入 Slint、Flutter、Qt 或其他 UI 运行时。
- 不重做现有菜单视觉设计和业务命令。
- 不在本次 Windows 修复中承诺绕过 Wayland 对窗口绝对定位和置顶的协议限制。
