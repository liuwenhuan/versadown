# 多云盘 Rust 接入设计

**日期：** 2026-09-09  
**状态：** 已确认，待实施计划审阅

## 目标

在“我的网盘”中接入百度网盘、天翼云盘、阿里云盘和迅雷云盘。用户完成登录或授权后，管理页显示服务对应的标签页，并提供与现有夸克、PikPak 一致的文件管理能力：目录浏览、上传、新建目录、重命名、移动、复制、移入回收站和下载。

所有服务端通信由应用内 Rust 后端发起；不会捆绑、调用或依赖第三方 CLI，也不会通过外部服务中转用户凭据或文件数据。

## 授权与凭据

每个服务声明其实际可用的授权能力：官方网页/扫码授权、账号密码登录，或两者。界面仅呈现适配器明确支持的入口。

- 网页或扫码授权在独立的官方服务页面中完成；Rust 后端只读取完成验证所必需的会话数据。
- 服务支持账号密码登录时，授权卡显示与 PikPak 一致的账号和密码输入框。密码仅用于当前 Rust 登录请求，使用 `Zeroizing` 清零，绝不写入日志、任务库或持久化凭据。
- 服务不支持稳定的账号密码流程时，不显示无效的密码入口，而是明确引导官方网页或扫码验证。
- 会话数据按服务保存为专属、最小化的结构，例如 Cookie 组合、刷新令牌、设备标识与必要校验字段。数据经现有 Windows DPAPI 加密后才写入本机。
- 新登录必须先成功校验账号信息与根目录访问，才可替换原有凭据；失败不得覆盖仍有效的已保存会话。

## 后端架构

`CloudProvider` 扩展为 `Baidu`、`Tianyi`、`Aliyun` 和 `Xunlei`。每家服务拥有独立 Rust 适配器，统一纳入现有云盘命令边界，并实现：

1. 账号恢复和会话刷新；
2. 根目录及子目录列表；
3. 新建目录、重命名、移动、复制和移入回收站；
4. 上传初始化与文件上传；
5. 为指定文件获取即时下载链接和必需请求头。

通用命令层只负责调度、DPAPI 凭据隔离、并发序列化和标准错误映射。服务协议细节不得泄漏到 React 层或 aria2 任务存储。

## 下载与重复任务

云盘任务继续使用稳定来源 `cloud://<provider>/<encoded-file-id>` 保存到任务库。短时下载地址及 `Cookie`、`Referer`、`User-Agent` 等请求头仅在立即提交给 aria2 时存在，绝不持久化。

重试、续传或重复任务重新解析稳定来源并由适配器刷新下载链接，沿用当前重复下载决策：可续传时续传；完整文件存在时提示打开位置；已记录但文件不存在时明确提示将重新下载；覆盖旧文件需用户确认。

## 前端体验

“网盘管理”显示六个服务授权卡。成功恢复或完成授权后，显示相应的“<服务>网盘”标签页；未授权的服务不创建空标签页。

现有 `CloudManager` 与 `CloudWorkspace` 保持通用。它们依据适配器返回的授权能力动态显示网页/扫码按钮或账号密码表单，并复用现有文件列表、工具栏、右键菜单、选择、多文件操作和下载入口。

## 错误处理

错误必须可操作且服务无关地映射为：未授权、凭据过期、等待网页/扫码完成、需要额外安全验证、服务拒绝请求、传输失败、响应格式异常和无法获取下载地址。

仅在适配器确认会话无效时才提示重新授权；不得把参数、请求头或协议不兼容错误笼统归类为“链接过期”。临时下载地址过期时，先刷新地址并重试一次。

## 测试与交付

- 为每个适配器增加模拟 HTTP 契约测试，覆盖登录/刷新、账号验证、目录及文件操作、下载链接和请求头。
- 验证失败不会覆盖旧凭据，明文密码不会进入持久化存储，稳定任务来源不会保存短链或 Cookie。
- 扩展前端测试，覆盖服务能力决定的登录入口、授权成功后的标签页以及通用文件管理调用。
- 运行全部 Rust 与前端测试、TypeScript 构建，并使用 `tauri build --no-bundle` 编译可运行 Windows 二进制；不生成安装包。

## 非目标

- 不实现服务端账号托管、代理转发或共享凭据。
- 不执行、分发或嵌入第三方 CLI；它们只能作为协议兼容性参考。
- 不实现分享、离线下载、会员功能或其他未被现有文件管理器暴露的服务特性。
