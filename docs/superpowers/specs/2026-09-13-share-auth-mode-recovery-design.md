# 多授权模式分享恢复设计

**日期：** 2026-09-13
**状态：** 已获用户确认

## 目标

分享解析、分享下载和个人网盘下载必须接受用户当前选择的授权方式。账号密码登录与网页授权都是同等有效的来源；代码只根据某个分享接口所需的实际会话载体（Cookie、App 签名会话或 Bearer token）判断可用性，不能把 `auth_method` 当作“只有网页登录才能分享”的开关。

## 已确认的约束

- 用户已经明确要求天翼、百度及其他支持账号密码登录的网盘同时支持账号密码与网页授权。
- 没有已保存密码时，不能为了分享静默要求或假定密码登录；网页授权会话失效时仍走官方网页授权。
- 只有真实的认证失效可以进入恢复链路；分享访问码错误、验证码和风控提示不能触发密码重登。
- 读取分享可在恢复一个有效会话后重试一次；已开始转存、删除或下载传输的有副作用操作不能被自动重放。
- 天翼的 App 签名会话和官方浏览器 Cookie 是同一账号的两条独立传输通道，刷新任一通道不得清除另一通道。

## 设计

### 公共恢复语义

`inspect_cloud_share` 使用的会话工作器改名为中性的 `run_share_session_read_work`。它仍委托已有的 `AuthSupervisor`：先尝试会话刷新，再在保存了密码且用户未选择“浏览器密码登录优先”时使用密码恢复，最后从已有官方浏览器 profile 捕获有效会话。该名称和注释不再暗示网页登录是唯一有效路径。

认证失败仅由 `AuthorizationExpired` 与 `NotAuthorized` 进入该恢复顺序。`WebAuthorizationRequired`、分享访问码缺失或错误、验证码和风控均直接保留原有用户交互语义。

### 天翼的分享传输会话

天翼分享 API 使用浏览器 Cookie；个人目录可使用 App 签名会话。`TianyiShareAdapter` 获取会话时遵循以下顺序：

1. 有可用的已保存 Cookie 时直接发起分享请求。
2. Cookie 缺失而 App 会话存在时，通过 SSO 换取 Cookie，校验身份 Cookie 并持久化完整 Cookie jar（包括 `JSESSIONID`）。
3. Cookie 非空但分享接口明确返回认证失效、且 App 会话存在时，仅对该安全 GET 请求换取一次新 Cookie、持久化后重放该请求一次。
4. 没有可转换的 App 会话时，返回原始认证错误，由公共恢复链路按用户原有方式处理。

新的 Cookie 必须同时更新分享请求的 Cookie 和持久化的 `TianyiSession`，保留 `app`、浏览器标识和 User-Agent。换取失败、验证码或风控绝不循环重试。

### 各服务的授权契约

| 服务 | 密码登录产物 | 网页授权产物 | 分享适配器契约 |
| --- | --- | --- | --- |
| 天翼 | App 签名会话，可换取浏览器 Cookie | 浏览器 Cookie 与上下文 | 以 Cookie 发分享；可从有效 App 会话补齐或更新 Cookie。 |
| 百度 | 标准化的 `BDUSS` Cookie | 标准化的 `BDUSS` Cookie | 不读取 `auth_method`，只校验 Cookie。 |
| PikPak | Bearer token | Bearer token | 不读取 `auth_method`，只校验 token 与设备信息。 |
| 夸克、阿里、迅雷、UC | 当前没有 Rust 直接密码登录 | 官方网页会话或公开分享令牌 | 不新增密码回退；保持适配器按其现有传输凭据工作。 |

## 验收与回归矩阵

1. 天翼 App-only 会话能换取 Cookie 并解析分享。
2. 天翼含失效 Cookie 的 App 会话在第一次分享认证失败后换取新 Cookie，仅重试同一请求一次并持久化新 Cookie。
3. 天翼网页 Cookie 会话不触发 App SSO 换取。
4. 百度 Password 与 Web 标记的有效 Cookie 都可以走同一分享解析路径，失效 Cookie 都返回可恢复的认证错误。
5. PikPak Password 与 Web 标记的有效 token 都走同一分享解析路径。
6. 分享访问码、验证码、风险验证不会被包装为密码恢复。

## 不在范围内

- 不新增任何网盘账号密码登录能力。
- 不保存用户未选择保存的密码，也不规避网盘官方验证码、短信或风控流程。
- 不改变分享访问码的交互与下载/转存的幂等保障。
