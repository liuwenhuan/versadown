# 网盘驱动与长期授权重构规格

## 目标

在不改变现有七个网盘用户功能和稳定下载来源格式的前提下，完成以下六个项目：

1. 修复已确认的凭据、分页和重复验证问题。
2. 建立后端唯一的网盘描述与能力注册表，前端通过后端目录渲染网盘。
3. 将命令层中的网盘分发收敛到内部驱动接口，并按授权、文件管理、下载、分享、上传拆分职责。
4. 建立账号长期授权管理器，统一刷新、静默恢复、持久退避和授权成功后的失败任务恢复。
5. 拆分分享能力、改进分享计划存储和下载源锁，避免长时间网络轮询占用会话锁。
6. 将上传请求改为流式文件切片，并由核心调度器实施有界并发。

## 不变量

- 继续支持 `quark`、`pikpak`、`baidu`、`tianyi`、`aliyun`、`xunlei`、`uc` 七个网盘。
- 每个网盘只维护一个账号；新账号覆盖该网盘旧账号、旧密码和旧会话。
- `cloud://`、`cloud-share://` 等已持久化下载来源格式保持兼容。
- 临时签名下载地址不得写入任务数据库或分享计划。
- 读取类操作在会话静默恢复后最多自动重试一次；重命名、移动、复制、删除和上传等修改操作不得自动重放。
- 主程序继续拥有 DPAPI 凭据、WebView、任务数据库、下载引擎、文件系统和分享清理日志；网盘驱动只实现协议。
- 不保留常驻隐藏 WebView。需要浏览器兜底时按需创建，完成凭据捕获后关闭。
- 已保存密码不得返回到前端；前端只知道用户名和是否存在已保存密码。
- 未知过期时间的 cookie 会话不得通过高频保活维持；仅首次使用、恢复或实际鉴权失败时检查。
- 设备标识和浏览器配置目录按网盘账号稳定复用，避免无意义设备漂移触发风控。

## 内部驱动边界

后端提供唯一 `ProviderRegistry`，每个条目包含：

- `ProviderDescriptor`：ID、显示名称、根目录、回收站、授权策略、分享链接规则、可信域名、上传与文件能力、并发限制。
- `DriveOps`：账号、分页目录、建目录、重命名、移动、复制、移入回收站、永久删除、恢复。
- `DownloadOps`：个人文件稳定来源和当前下载信息解析。
- `ProviderAuth`：恢复、验证、刷新、保存密码静默登录和 WebView 授权配方。
- 可选 `UploadOps`、`ShareInspect`、`ShareTransfer`、`RecordedTransferResolver`。

本次只实现进程内静态驱动接口。外部插件 ABI、插件商店和第三方代码加载不在本次范围，但接口不得依赖 Tauri 命令或具体页面组件。

## 长期授权状态

每个网盘维护持久化的授权维护记录：

```text
Disconnected -> Restoring -> Ready -> Refreshing -> Ready
                                      -> NeedsSilentRelogin
                                      -> NeedsInteractiveAuth
                                      -> RiskBlocked
```

记录至少包含 `schema_version`、`provider`、`account_id`、`auth_method`、`session_revision`、`expires_at`、`next_refresh_at`、`consecutive_failures`、`next_allowed_attempt_at` 和 `health`。敏感会话正文继续由各网盘加密存储；维护记录不包含密码、cookie 或 token。

恢复顺序固定为：

1. refresh token 或 App session 刷新；
2. 已保存密码静默登录；
3. 持久浏览器配置按需静默捕获一次；
4. 显示官方网页授权。

已知过期时间的会话在有效期约 80% 或过期前 5 分钟触发刷新，并加入 30 至 120 秒随机抖动。失败退避持久化为 5 分钟、30 分钟、2 小时；连续失败后停止自动登录，等待用户操作。单个网盘同一时刻只允许一个刷新或静默登录，但普通读取和传输不占用刷新锁。

## 前端契约

- `cloud_provider_catalog` 返回全部网盘描述和能力；前端不再硬编码七个网盘数组、标签、根目录或授权方式。
- 账号恢复结果逐个呈现，一个慢网盘不得阻塞整个“我的网盘”页面。
- `cloud_saved_password_credentials` 替换为只返回 `{ username, hasSavedPassword }` 的安全接口。
- 密码登录请求允许提交新密码，或明确选择后端已保存密码；空字符串不得被当成保存密码回传。

## 分享与上传

- 分享检查、解析、转存和已转存文件重新定位使用独立能力接口，缺少能力在注册表层面即可判定。
- 分享计划迁移到 SQLite 行记录；秘密载荷单独加密，旧版 `cloud-share-plans-v1.bin` 首次读取后原子迁移。
- 下载源锁只在存在调用者或等待者时驻留，任务完成后可回收。
- 上传正文支持内存字节和本地文件切片。大文件不得整体读入内存；默认并发 2，服务商描述可以降为 1。

## 验收

- 新增的行为均按 TDD 先看到目标测试失败，再实现至通过。
- 每个阶段运行直接相关的 Vitest 或 Rust 集成测试。
- 最终运行网盘相关前端测试、网盘相关 Rust 测试以及 `scripts/build-windows.ps1`。
- 只有定向测试暴露共享基础设施风险时才扩大到全量测试。
