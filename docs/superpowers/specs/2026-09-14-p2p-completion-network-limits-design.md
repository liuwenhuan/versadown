# P2P 完成状态与分享限速设计

## 目标

P2P 下载（BT、磁链和 ED2K）在文件字节下载完成时即成为完成任务，不因分享率尚未达到默认值 `1.5` 而停留在“下载中”。完成列表只在实际分享上传进行时，于完成时间后显示 `P2P 分享中`。

网络设置增加下载速度限制与仅作用于 P2P 分享上传的 `P2P 分享上传速度限制`。下载速度默认不限速；P2P 分享上传默认自动，并在启动和每小时测速后按上行测速结果的一半设定总上限。

网盘上传和传统 FTP 不属于 P2P 分享限速的作用对象。网盘上传期间，P2P 分享必须完全停止，以让出上行带宽。

## 任务状态

- 增加持久化字段 `p2p_sharing`，它是完成状态的附属运行态，而不是新的顶层 `TaskStatus`。
- 当 P2P 任务的 `completedLength == totalLength` 且 aria2 仍为活动分享状态时，任务状态写为 `completed`、立即写入完成时间、`p2p_sharing` 写为 `true`。任务进入“完成中”标签页。
- aria2 达到种子分享率并转为终态后，保持任务 `completed`，将 `p2p_sharing` 更新为 `false`。
- 已完成但 `p2p_sharing` 为真的任务仍须保留 aria2 GID 并继续轮询；应用或 aria2 重启后的第一次同步，根据活动 GID 和已完成字节恢复该运行态。
- 用户手动暂停、删除、取消分享，或自动策略临时暂停分享时，`p2p_sharing` 为 `false`。自动策略保留其自身的暂停来源，不能误恢复用户主动暂停的任务。

## 完成页显示

- 完成列表在完成时间后仅在 `p2p_sharing == true` 时显示 `P2P 分享中`。
- 分享率达到 `1.5`、用户暂停或自动策略暂停时不显示任何额外文字。特别地，不显示“等待测速”或“因网盘上传暂停”。
- 不新增“分享中”顶层标签页；完成任务始终在完成标签页。

## 网络设置

### 下载速度限制

- 作用于 aria2 下载流量（普通链接、FTP、BT、ED2K），默认“不限制”。
- 提供“不限制”和“自定义”两种模式；自定义值使用用户可见的带宽单位并同时在前后端校验。
- 不涉及网盘上传、网盘下载以外的传输控制器。

### P2P 分享上传速度限制

- 名称固定为 `P2P 分享上传速度限制`。
- 提供“自动”（默认）、“不限制”、“自定义”三种模式。
- 这是所有正在分享的 P2P 任务共享的总上行上限。控制器只接管识别为 P2P 的 GID；网盘上传和传统 FTP 任务不接收该设置，也不被暂停或恢复。
- 保持现有 `btSeedRatio` 默认值 `1.5`，该分享率设置与带宽上限相互独立。

## 自动模式

### 测速来源与隐私

- 使用 Cloudflare Speed Test 的官方 JavaScript 组件与上传测量端点。它通过 Cloudflare 全球边缘网络测速，并公开了可集成的上传端点与算法实现。
- 该测试衡量的是用户到 Cloudflare 网络的上行能力，不把它描述为所有远端站点的保证带宽。
- 网络页须说明测速会向 Cloudflare 发送测试流量和网络测量信息；应用内测试设定 60 秒硬超时，超时立即停止。

### 运行规则

- 仅在“自动”模式启动测速。应用启动时先建立 P2P 分享闸门，再开始测速；在测速成功、失败或 60 秒超时前，不允许 P2P 分享上传开始。普通下载和网盘传输不等待测速。
- 从测速结果取上传速率，设定有效 P2P 总上传上限为该结果的 `50%`，并持久化最近一次成功的测速上限与时间。
- 应用运行期间每小时复测一次。复测时暂时停止 P2P 分享，得到新结果后以新上限恢复；若失败，使用上一次有效上限恢复。
- 第一次测速失败且没有历史结果时，使用保守的 `256 KiB/s` 作为有效上限，并在网络设置页标明测速未完成；不把失败解释为不限速。
- 用户选择“不限制”或“自定义”时不自动测速；切回“自动”时立即启动一次测速。

### 网盘上传让行

- 任一网盘上传任务进入实际上传态时，立刻暂停所有正在进行的 P2P 分享，使 P2P 实际上传为零。
- 由于 aria2 的限速值 `0` 表示不限速，而不是零上传，不能通过设置该值实现让行；应暂停被自动策略接管的 P2P 分享 GID。
- 当所有网盘上传任务结束后，仅恢复因本策略暂停的 P2P 任务，并恢复测速或用户配置此前确定的有效上限。用户自行暂停的任务不自动恢复。
- 自动暂停期间完成页不显示 P2P 分享文案。

## 同步与错误处理

- P2P 分享控制器独立负责：测速状态、已持久化的有效上限、自动暂停来源、P2P GID 的暂停/恢复，以及向 aria2 更新运行时选项。
- aria2 RPC 设置失败时，保留最后一次确认已生效的值，记录可诊断错误并向设置页反馈；不得错误地把未生效的目标值显示为当前限制。
- 无效自定义带宽（空值、非数值、零以下或超过安全上限）必须在前端和后端拒绝。
- 测速、轮询和限速失败不得改变文件完成状态或把完成任务退回“下载中”。

## 验证

- Rust：验证 P2P 已下载完但仍活跃时进入 `completed + p2p_sharing`，分享终态清除标记，重启同步恢复标记，自动暂停不恢复用户暂停任务，以及云上传让行。
- Rust：验证 aria2 运行时选项更新、测速成功/失败/超时、每小时复测和配置持久化。
- 前端：验证完成标签页的位置与 `P2P 分享中` 显示/移除，自动暂停时无附加文案，以及网络页三种 P2P 模式、默认值、校验和当前有效速度。
- 运行相关前后端定向测试（Vitest 排除 `.worktrees/**`）和 Windows 发布构建；不默认运行全量测试。
