# 网盘账号容量卡片与变更刷新设计

日期：2026-09-15

## 目标

在“我的网盘”中已经登录或取得授权的网盘账号卡片上，显示当前账号已经使用的容量和总容量。上传、复制、分享转存、回收站操作或永久删除改变云端占用后，卡片应及时刷新；容量接口临时失败不能把账号误判为掉线，也不能清除最后一次成功取得的数据。

本设计覆盖当前七个网盘：夸克、PikPak、百度、天翼、阿里云盘、迅雷和 UC，并将现有分享转存预检中的容量查询抽成提供方无关的公共能力，为后续连接器插件化建立稳定契约。

## 非目标

- 不持久化容量历史，不提供容量趋势图。
- 不通过周期轮询持续请求网盘容量。
- 不把容量可用性与登录状态绑定；容量失败不触发退出登录。
- 不为移动、重命名或新建空目录等不改变字节占用的操作刷新容量。
- 不在本次改动中增加多账号管理；容量始终绑定当前提供方唯一账号。

## 统一容量模型

将当前位于分享模块的 `CloudTransferCapacity` 提升为云盘公共模型 `CloudStorageCapacity`：

```rust
pub enum CloudStorageCapacity {
    Limited {
        total_bytes: u64,
        used_bytes: u64,
    },
    Unlimited {
        used_bytes: u64,
    },
}
```

模型必须保证有限容量满足 `used_bytes <= total_bytes`。`Unlimited` 仍保留已用字节数，使卡片可以显示“已使用 12.3 GB / 不限容量”。未知容量不是模型中的一种成功值，而是命令错误；这样不会把“接口暂时不可用”错误解释为无限容量。

IPC 返回值附带提供方和账号标识：

```rust
pub struct CloudAccountCapacity {
    pub provider: CloudProvider,
    pub account_id: String,
    pub capacity: CloudStorageCapacity,
    pub updated_at: String,
}
```

前端只接受与当前卡片 `provider + accountId` 完全一致的结果，防止账号切换期间的迟到响应污染新账号。

## 提供方能力

在云盘能力层增加与分享条目无关的只读接口：

```rust
fn storage_capacity(&self) -> Result<CloudStorageCapacity, CloudError>;
```

现有百度、阿里、夸克、UC 和迅雷的 `transfer_capacity` 实现改为委托给 `storage_capacity`，分享预检继续复用同一返回模型，不再保留两套解析逻辑。PikPak 和天翼使用各自当前登录会话补齐容量请求，并复用已有请求头、设备标识、令牌刷新及风控错误映射。

公共解析器接受 JSON 整数或十进制字符串，拒绝缺失、负数、非整数、溢出以及有限容量中已用大于总量。只有提供方协议明确声明的特殊值才能映射为 `Unlimited`。

新增 Tauri 命令：

```text
cloud_account_capacity(provider)
```

命令先取得当前账号，再通过该提供方受监督会话读取容量，并把账号 ID 写入响应。认证过期继续进入现有静默刷新或交互授权流程；普通容量接口失败只返回容量错误，不修改账号状态。

## 卡片状态与显示

授权账号卡片在账号名称下方增加一行容量信息：

- 初次请求：`容量获取中…`
- 有限容量：`已使用 12.3 GB / 100 GB`
- 无限容量：`已使用 12.3 GB / 不限容量`
- 首次失败：`容量暂不可用`
- 已有成功值后刷新失败：保留原数值，并附加 `更新失败`

容量使用现有字节格式化规则。容量行属于辅助信息，不影响登录、重新授权、进入文件列表或退出登录操作。

前端以内存缓存保存每个 `provider + accountId` 最后一次成功结果。退出登录或同一提供方换号时删除旧缓存；应用重启后重新读取，不新增容量数据库表。

## 变化通知与刷新

后端增加 `cloud-capacity-invalidated` 应用事件，载荷只包含：

```text
provider, accountId, reason
```

以下操作成功且确实产生变化后发送事件：

- 上传完成至少一个文件；
- 云盘内复制完成；
- 分享文件转存完成；
- 移入回收站、从回收站恢复或永久删除完成。

失败、取消和零项操作不发送事件。移动、重命名和新建空目录不发送事件。

前端订阅事件，只让匹配账号的卡片失效并重新调用容量命令。同一账号短时间内连续收到多个事件时使用 400 毫秒 trailing debounce 合并为一次查询，避免批量上传或删除产生请求风暴。组件卸载、退出登录或账号切换时取消尚未执行的刷新。

如果某个操作响应已经包含可信的新容量，后端可以直接发送带容量值的更新事件；第一版统一使用失效事件和单独只读查询，保持各提供方写操作返回结构简单。

## 错误与会话语义

- 网络超时、响应字段变化和临时服务错误：保留最后容量，标记更新失败。
- 第一次容量查询失败：显示容量暂不可用。
- 明确认证过期：沿用认证监督器恢复；最终需要交互授权时仍由现有授权流程处理。
- 风控或验证码：保留结构化错误供现有授权提示使用，同时不清除最后容量。
- 账号退出或被覆盖：立即清除该账号容量，迟到响应因账号 ID 不匹配而丢弃。

卡片不显示原始接口错误、token、cookie、手机号或账号内部标识。

## 测试策略

### Rust

- 公共容量模型解析有限、无限、字符串数字和非法边界。
- 七个提供方分别验证正确请求、字段解析和认证错误透传。
- 原有五家分享容量预检委托公共能力，结果与改造前一致。
- 容量命令返回当前账号 ID，不接受无账号会话。
- 上传、复制、分享转存、回收站和永久删除成功时发送失效事件；失败或零项操作不发送。

### 前端

- 卡片覆盖加载、有限、无限、首次失败和保留旧值的刷新失败状态。
- 登录成功后自动查询容量。
- 账号切换清理旧容量，并忽略旧请求迟到结果。
- 变化事件触发刷新；短时间连续事件只查询一次。
- 不匹配的提供方或账号事件不刷新当前卡片。
- 容量失败不会改变“已经登录/已经完成授权”状态。

### 构建与验收

- 运行容量相关 Rust 单元测试和 CloudManager/CloudWorkspace 前端定向测试。
- 运行 TypeScript 检查及 Windows release 构建。
- 对至少一个支持上传、一个支持分享转存、一个支持回收站永久删除的真实账号验证容量变化；若提供方容量统计存在服务端延迟，允许事件后一次短延时重试，但不启用长期轮询。

## 完成标准

- 七个已授权网盘卡片都能显示当前账号容量或明确的暂不可用状态。
- 五家已有容量实现与分享预检共用同一能力，不复制解析代码。
- PikPak 和天翼容量查询接入现有会话生命周期。
- 影响占用的成功写操作会自动刷新对应账号卡片，并对批量事件合并请求。
- 临时容量失败保留旧值且不影响登录状态。
- 定向测试、类型检查和 Windows release 构建通过。
