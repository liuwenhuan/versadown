# 夸克下载连接预算设计说明

## 目标

仅改变夸克网盘（个人文件与夸克分享文件）的下载调度。每个夸克下载任务的连接预算 `B` 等于当前系统设置
`aria2.max_connections_per_server`（取值 1–16）。

对一个目录下载根任务，所有尚未结束的文件共享这一个预算：每个文件先保留 1 个连接；只有待下载文件数小于
`B` 时，才把剩余预算分配为某些已提交文件的 Range 并发。单个普通夸克文件视为只含一个文件的任务，也使用
同一规则。不同目录根任务之间仍保留既有的全局/提供商任务准入规则，不合并成一个全局连接池。

## 不变量

- 分配量以 aria2 每任务的 `split` 与 `max-connection-per-server` 的目标值计量；对同一目录根任务，所有文件的分配和不超过 `B`。
- 未结束的目录条目（包括尚未生成 GID 的条目）会预留一个基础单位。因此新的文件一旦被 aria2 接纳，不会因前一个文件已经扩容而短暂超过预算。
- 新目录文件在尚无 GID 时始终以 1 个连接提交；aria2 接纳并保存 GID 后才在下一次重算中扩容。这样首次提交和既有文件的目标值在任意瞬间都不越过预算。
- 当文件的可信剩余字节数小于 `1_048_576`（1 MiB）时，其目标值必须为 1；未知剩余大小也不参与加速分配。恰好 1 MiB 仍可参与分配。
- 额外连接按稳定顺序轮转发给可加速文件；一个可加速文件时可获得全部余量，多个文件时先各得一个再继续轮转。
- 暂停、取消、失败、完成、GID 替换和设置变更均会触发重新计算。调整失败不改变下载任务状态，也不得让调度器静默从头下载或重新提交 URL。

## 范围边界

调度状态、预算算法、轮询与 aria2 `changeOption` 均位于夸克插件私有模块。现有共享目录调度器、提供商注册表和其他网盘的策略不承载这项策略。

目前目录任务的入队、URL 提交和 aria2 状态同步都在通用命令层，夸克插件没有独立生命周期回调。因此需要在 `cloud/commands/download.rs` 保留一个很小的夸克分流点：仅调用插件的“初始选项/唤醒协调器”接口，不保存状态、不含预算判断、也不改变其他提供商的代码路径。没有该分流点，插件既不能在提交前将新文件预留进预算，也不能保证严格上限。

为避免把夸克策略写入下载引擎共享服务，插件从当前受锁保护的本地 aria2 设置构造短生命周期的 loopback RPC 客户端，并且只调用已存在的 `aria2.changeOption`。RPC Token 不写日志、不持久化到插件状态；每次调用都会用任务 ID 和当前 GID 重新校验目标。
