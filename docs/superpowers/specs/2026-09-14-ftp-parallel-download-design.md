# FTP 并发分片下载设计

## 目标

为进程内 `FtpDownloadEngine` 增加与 HTTP/HTTPS（aria2）一致的两层并发语义：

- `Aria2Settings.max_concurrent_downloads` 限制同时传输的 FTP 任务数量；
- `Aria2Settings.max_connections_per_server` 是单个 FTP 任务可使用的最大分片连接数。

默认值不变：最多 5 个 FTP 任务同时传输，每个任务最多 8 条 FTP 数据连接。服务器不支持安全分段读取时，下载必须自动降级为现有的单连接、顺序续传；不能把该情况作为用户可见失败。

## 引擎边界与配置

FTP 仍由进程内 Rust 引擎处理，绝不提交给 aria2-next（后者没有 FTP 支持）。`EngineRuntime` 在创建 `FtpDownloadEngine` 时传入当前 aria2 设置，并在 `reconfigure_aria2_settings` 成功时将新并发值同步给 FTP 引擎。设置变更对尚未开始的任务立即生效；正在传输的任务保持既有分片数，直至暂停、恢复或完成，以避免在传输中重排字节区间。

FTP 引擎新增任务调度层：提交、恢复和继续操作只会将任务置为 `Queued` 并交给调度器；调度器只在活跃 FTP 任务数小于 `max_concurrent_downloads` 时启动一个任务。任务完成、失败、暂停或取消时释放名额并唤醒下一项。现有全局统计继续从任务状态计算，因此 `num_active` 和 `num_waiting` 自然反映该限制。

## 分段传输与状态持久化

下载前，控制连接按二进制模式读取 `SIZE`。有确定总大小、文件未完成、并且配置允许多个连接时，引擎使用独立连接探测 `REST` 对非零偏移量的支持。探测成功后，按 `min(max_connections_per_server, ceil(total / 4 MiB))` 计算分片数，至少为 1；该值是上限而非保证值。

每个分片保存 `start_offset`、`end_offset` 和已确认字节数。新增 SQLite 分片表，以任务 ID 和分片编号为键；写入文件后定期持久化所属分片进度，恢复时从最后已确认的偏移量重新请求该分片。该顺序允许崩溃后少量重下已写入字节，但不会把未确认的孔洞误判为已完成。

开始分片前，将输出文件安全设为远端总长度；各分片以各自文件句柄定位后写入其负责的区间，绝不截断整个文件。聚合所有分片已确认字节，持续更新既有任务的总大小、已完成字节、速度、ETA 和连接数。只有全部分片达到各自区间末尾，任务才标记为 `Completed`。

已有单连接任务或旧数据库任务没有分片记录时，恢复逻辑维持当前“本地文件连续前缀 + REST”续传路径；首次成功采用分片模式时才建立分片记录。任务完成、取消或回收时删除分片记录。

## 降级、暂停与错误处理

以下情况在未向输出文件写入任何分片数据前自动切换到单连接下载：`SIZE` 不可用、总大小为零或太小以至只需一个分片、服务器拒绝非零 `REST`、或分片初始化失败。降级时清除未使用的分片状态，并以现有单流方式从本地连续前缀续传。

分片已经开始后，某一工作连接的网络、认证、FTP 协议或本地写入错误会停止其同任务分片并将任务标记为失败；不会在已有并行写入后切换为单连接，以免掩盖范围不一致或数据损坏。错误信息继续脱敏，不含 FTP URI 的用户名或密码。

暂停、取消和应用退出向该任务全部分片发送协作式取消信号，等待它们退出后保留已确认分片进度。恢复和应用重启会重新排队，由调度器按上限启动未完成分片。各重新建立的连接使用 `REST(start_offset + confirmed_bytes)`，所以无需 `.part` 文件。

## 兼容性

- FTP 自定义 HTTP 请求头和 HTTP 代理限制保持不变。
- HTTP/HTTPS 仍由 aria2 管理；本改动不改变其启动参数、分片策略或任务状态。
- 连接数 UI 显示活跃 FTP 数据连接数；单连接降级时显示 1。
- 外部服务器可限制同时会话数；此时下载会在安全降级前尝试分片，或在分片已开始后报告可重试失败，不绕过服务器限制。

## 验证

新增或扩展 `src-tauri/tests/ftp_download.rs` 的本地受控 FTP 服务测试：

1. 分片模式使用多个非零 `REST` 偏移量，并下载出与原始 payload 完全一致的文件；
2. 并发任务数不超过设置值，排队任务在名额释放后启动；
3. 配置中的单任务连接上限控制活跃数据连接数量；
4. 服务器拒绝 `REST` 时自动完成单连接降级；
5. 分片下载的暂停、恢复、进程重启恢复及失败重试不会产生数据空洞或凭据泄漏；
6. 设置变更会更新 FTP 调度器，且不影响 HTTP aria2 参数的既有测试。

按项目规则，只运行上述 Rust 定向集成测试及与改动模块直接相关的 Rust 单元测试；最后运行 `scripts/build-windows.ps1` 作为发布构建验证，不默认执行全量 Rust 或前端测试。
