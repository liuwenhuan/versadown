# 全网盘分享链接下载设计

## 目标

在“新建下载链接”中识别夸克、PikPak、百度、天翼、阿里、迅雷、UC 的分享链接，解析其中的文件或目录，并进入现有 aria2 下载队列。

- 单个普通文件自动开始下载；目录或多个文件显示可选择的确认清单。
- 优先使用服务商分享 API 返回的直链，并把当前已登录/授权的会话、会员身份、必需的 User-Agent、Cookie、Referer 与授权头传给 aria2。
- 只有没有可用分享直链且服务商协议要求时，才转存到已登录的个人网盘后下载。已登录时自动转存；未登录时不创建任务，提示先登录对应网盘。
- 增加设置项“分享转存下载完成后自动删除转存文件”，默认开启。关闭时保留转存文件；任何清理只作用于本应用本次转存并记录的对象。

## 非目标

- 不在任务 SQLite 中保存分享 URL、提取码、Cookie、access token、share token 或签名 URL。
- 不把分享页 HTML URL 直接提交给 aria2。
- 不为转存文件做未经识别的全盘扫描或批量删除。

## 用户流程

1. 用户在新建下载窗口粘贴链接；解析器从 URL 或相邻文本提取 `pwd`、提取码、访问码。窗口提供可选访问码输入，供链接未携带访问码时重试。
2. 如果文本中恰好只有一个受支持的分享 URL，后端按服务商规范化并取得分享清单；多个候选要求用户选择，不默认取第一个。
3. 后端建立加密的分享计划。一个文件立即创建下载任务；目录或多文件返回资源列表，用户选择后再创建实际下载任务。
4. 下载前和每次短链失效重试时，任务从加密分享计划重新获得直链与请求头。各文件继续使用既有 aria2、续传、重复任务和失败恢复逻辑。
5. 转存下载完成后，若设置启用，后台仅删除本计划在该服务商转存成功的对象；删除失败不影响本地下载完成，但会在任务状态中显示可重试的清理提示。

## 统一模型

新增 `CloudShareAdapter`，每个服务商实现以下职责：

- `recognize`：识别 URL、规范化分享 ID 与可选初始目录。
- `inspect`：使用访问码和可用登录会话分页、递归生成安全的文件清单与目录相对路径。
- `resolve_download`：为指定分享文件获得当前直链和 aria2 所需 headers；直链不可用时声明需要转存。
- `materialize`：仅在需要时转存，并返回可由现有个人盘 `cloud://provider/file-id` 流程刷新下载地址的对象；同时记录精确的清理目标。

加密的 `CloudSharePlan` 存在 DPAPI 保护的固定存储键中，带版本、创建/最后使用时间、服务商、规范化分享标识、访问码、会话相关 token、已选文件和转存清理记录。计划数量与保留时间均有限制。普通任务来源只存不透明稳定标识，例如 `cloud-share://provider/<share-fingerprint>/<entry-fingerprint>`；fingerprint 使用不可逆散列，不含访问码或 token。

## 服务商策略

| 服务商 | 首选 | 无直链时的处理 |
| --- | --- | --- |
| 夸克 | 分享 API 直链（带已登录 Cookie/UA） | 已登录自动转存，复用个人盘稳定下载 |
| PikPak | 分享 API 直链（带 Web captcha/会话上下文） | 明确服务端限制；不伪造会员权限 |
| 百度 | 尝试分享 API 直链与当前 Netdisk 身份 | 协议要求时自动转存到个人盘后下载 |
| 天翼 | 分享 API 直链（会话、访问码和必要 headers） | 登录后按官方可用转存路径处理 |
| 阿里 | 分享 token + 分享下载 URL | 仅在 API 明确要求登录/转存时使用个人盘 |
| 迅雷 | 分享 API 直链（分享 captcha 上下文） | 已登录自动转存并等待转存任务完成 |
| UC | 分享 token + Cookie/CSRF/桌面 UA/Origin/Referer 直链 | 已登录后按可用转存路径处理 |

认证、验证码、风控、访问码错误、链接失效、禁止下载、会员/区域限制和转存容量不足均返回结构化错误，并映射为用户可执行的提示；不会循环重试网页验证。

## 接口与 UI

- 扩展下载输入分类为七家 `CloudShare`；原有直链、种子、磁链行为不变。
- `parse_download` 返回可区分的分享解析结果，而非伪造单个 aria2 任务。新增确认命令按选择结果创建多个任务。
- 解析/确认弹窗显示来源网盘、文件名、大小、层级、是否需要转存；对自动转存使用非阻塞状态提示。
- 设置中新增默认开启的 `deleteTransferredShareFilesAfterDownload`；任务详情显示自动清理结果。

## 安全与恢复

- DPAPI 是分享计划与访问码的唯一持久化位置；aria2 参数仅在即时提交时持有签名 URL 和 headers。
- 遇到 HTTP 401/403/412、签名过期或服务商指定的 URL 失效码时，重新解析/刷新一次；登录失效走已有会话续期，必须网页验证时引导用户授权。
- 同一服务商、同一分享文件使用无敏感 fingerprint 做重复检测。删除分享计划前保留已存在任务的必要恢复上下文；无法恢复时明确要求重新分析分享链接。

## 验收与测试

- 七家 URL 识别，含短链、目录初始路径、`pwd` 和粘贴文本中的提取码；多个链接不默认选择。
- 各服务商 mock transport 覆盖无访问码/错码/失效、分页递归、禁下载、会话过期、风控、直链携带 headers、短链刷新和会员限制。
- 单文件自动入队；目录和多文件确认后保留相对路径；既有重复下载与断点续传仍生效。
- 验证 SQLite、调试日志和 UI 事件中均不出现访问码、Cookie、token 或签名 URL。
- 转存成功、下载成功、自动删除成功/失败、设置关闭、未登录需要登录的全部路径均有测试。
- 每个已授权服务商以用户提供的可用分享文件和小目录做实机验证；不使用未授权的公开链接作为测试样本。
